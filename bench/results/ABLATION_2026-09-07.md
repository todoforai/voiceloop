# Four-arm hesitation ablation — 2026-09-07

## Decision

**Do not enable smaller capture packets at the current Flux endpoint settings.** Capture-only
reproduced the early provider boundary without fragmented pre-synthesis. Keep the active runtime
unchanged. Pre-synthesis-only passed this hesitation screen, but this fixture does not meaningfully
exercise its new fragmented-first-word path; its small timing difference is not a proven gain.

## Method

20 live conversations, six person turns each: **120 turns**, five conversations per arm. Same
Deepgram Flux (`flux-general-en`, eot_threshold=0.7), ElevenLabs TTS, fixed mock LLM, hesitation
PCM fixtures, v2.0 scorer and telemetry for every arm. Base commit b0d2ec2. Isolated copies; active
`src/` untouched. Smaller packets include the candidate's duration-preserving RMS/preroll changes.

- B: 4096-sample capture, original pre-synthesis.
- C: 512-sample capture, original pre-synthesis.
- P: 4096-sample capture, fragmented pre-synthesis.
- CP: 512-sample capture, fragmented pre-synthesis.

Predeclared order: B C CP P / C P B CP / P CP C B / CP B P C / P CP C B. First four blocks form a
balanced Williams square; fifth block is predeclared but cannot preserve perfect order balance.
All 20 runs retained. Collection 19:13–19:42 UTC. Dedicated browser/virtual audio stopped and real
mic/speaker defaults restored BEFORE CPU transcription. Same faster-whisper small.en/int8/config
for all 120 windows, no reference prompt. No OpenAI requests. No clean/echo/noise runs this round.

## New causal evidence

Every failure is the same scripted turn 4: “Send the confirmation to my email. [900ms pause]
Actually, make that a text message.” The user resumes ~2841ms into the turn. Raw provider events
now confirm an EndOfTurn for the prefix, followed by another provider turn for the continuation.

| Arm/run | Prefix EndOfTurn after scripted resume, ms | End-of-turn confidence |
|---|---:|---:|
| C3 | 283 | 0.7349 |
| C4 | 247 | 0.7642 |
| CP1 | 299 | 0.7422 |
| CP2 | 253 | 0.7749 |
| CP3 | 257 | 0.7915 |
| CP4 | 249 | 0.7412 |
| CP5 | 216 | 0.7583 |

All cross the unchanged 0.7 threshold. Example passing C1 reaches 0.6953, stays below threshold,
then drops to 0.0076 as the continuation is processed. Passing B1 peaks at 0.6255 in the comparable
pause interval. Provider `audio_window_start/end`, `turn_index`, sequence and available word fields,
callback monotonic time, packets and cumulative samples sent are saved without interpreting their
units as wall-clock ground truth. Callback-after-resume alone is NOT proof the server had already
processed the resumed phonemes; transport/provider buffering still needs isolation.

### What this establishes

- **Fragmented pre-synthesis is not necessary:** capture-only reproduced the split (2/5).
- **Smaller packets are associated with failure in this sample:** 7/10 small-packet conversations
  split, versus 0/10 large-packet conversations. This is not a population failure-rate estimate.
- These are **provider EndOfTurn decisions**, not speculative playback or VAD-triggered commit.
- The candidate preserves 4096-sample bootstrap RMS windows; nativeEOT bypasses VAD commit.
- **VAD never ended/restarted during the problematic pause** in these failed turns: it stayed
  active from ~190–272ms after turn start. A resume-generation-only guard would have no new
  VAD resume edge to consume. Blindly dropping finals while VAD is active also risks losing
  legitimate finals because VAD and provider endpoints have different timing.
- Extra user-message history entries make the count-based mock advance to the parking reply then
  “I have nothing scripted for this turn.” Two bad answers per split are coupled consequences,
  not independent failures. No real-world email/text tool was invoked.

### What is NOT established

The 2/5 C vs 5/5 CP difference does not prove a presynth interaction. The mock sends 12-character
LLM deltas, and all scripted replies' first deltas already contain a usable first-word boundary.
Recorded pre-synthesis hits cover **all accepted turns in every arm** (B30/C32/P30/CP35).
Consequently the fragmented lookahead improvement is largely unexercised here; the CP/C difference
can be sampling, transport phase, network/provider variation, or other timing effects. Do not label
this a proven presynthesis race or claim a measurable new presynthesis benefit from these rows.

## Next experiments, in order

1. **STT-only real-time packetization replay:** feed identical person PCM (including the full
   hesitation context/silence) at 512 vs 4096 samples, with no LLM/TTS. Vary packet phase in a
   predeclared order; log full provider boundary timing/confidence and sample positions. This
   separates provider ingress/packet-phase sensitivity from full-duplex feedback and TTS load.
2. **More conservative endpoint experiment, not a default change:** all observed false boundaries
   here are below 0.8 confidence, so test 0.8 alongside 0.7 with small packets. A threshold change
   may delay legitimate answers or produce later different boundaries; it cannot be validated by
   simply deleting logged EOTs. Measure clean latency, short answers, hesitation, echo and stalls
   live before accepting it. Keep v2 fidelity gate and add explicit split-provider-turn counts.
3. **Test fragmented pre-synthesis where it matters:** benchmark equivalent mock responses with
   first words deliberately divided across deltas, same fragmentation for all compared arms,
   while retaining 4096 capture. Confirm exact replay and tool gating. This isolates its actual
   benefit rather than attributing ordinary network variation to dead code paths.

Do not add a universal pause delay, silently merge arbitrary user messages, or change the mock
only for one system. Keep irreversible tools behind explicit user authorization where appropriate;
TTS abort does not undo an already authorized side effect. No runtime fix is shipped from this run.
