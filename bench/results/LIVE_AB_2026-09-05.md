## Confirmed legacy barge-in scoring caveat

The unmodified analyzer marks the first ending audio segment overlapping an interruption as barge_stop. In the new recordings, output resumed before the person finished speaking after that credited stop on **5/10 original and 4/10 patched interruptions**. Thus some legacy stop times measure an inter-sentence pause, not sustained yielding.

Diagnostic last audible segment end before the interrupting utterance finished, relative to its start (same turn order across each arm):
- Original: 1193, 1641, 1176, 1658, 1075, 1614, 1218, 1571, 1051, 1712ms.
- Patched: 1123, 1630, 1211, 1723, 1137, 1507, 1085, 1677, 1197, 1542ms.

Using the same upper-median convention, these are **1571ms original vs 1507ms patched**. This is a separate, post-hoc diagnostic, not a validated replacement leaderboard score. It must not be substituted into only our row while retaining competitors' first-segment stop scores. A proper sustained-yield metric should be specified, tested and recomputed for every available recording.

## What was actually changed and exercised

Original: git HEAD b6c9d27be689c42d809bce4192faea1015f9f722 (0.1.10).
Patched: only runtime difference is StreamingTTS abort-aware blob wait and skipping canceled queued synthesis. No capture, endpointing, provider, prompt, sentence splitting, or prefetch setting changed. Runtime dependencies are byte-identical. Test-file differences do not enter the browser.

The separate controlled test proved cancellation releases speak() before a held synthesis finishes (301.14ms → 0.38ms with a 300ms gate). This live scenario interrupts during audible speech, while the principal fix concerns waiting for synthesis. Ordinary ElevenLabs fetches are already abortable. Therefore this is a live regression/performance comparison, not evidence that the controlled result translates into faster normal acoustic barge-in.

## Method and limitations

- Deterministic interleaved order: original, patched, patched, original, original, patched, patched, original, original, patched.
- Both immutable runtime snapshots served by one copied benchmark server; server's only harness change is binding to 127.0.0.1.
- Same dedicated Chrome 138.0.7204.168 profile, Node v24.13.0, same PulseAudio/PipeWire devices and fixed audio files.
- Same unmodified driver, analyzer, metrics and run-n runner. Each run-n call collected one conversation; final summary pools five per arm using historical upper median and nearest-rank p95.
- This is a shared-session/steady-state experiment, not a cold-start benchmark. Variant navigation is followed by the runner's reload; both arms receive this same extra initialization.
- No concurrent benchmark; one active microphone capture verified. All completed status checks reported no SUT errors.
- Audio latency and stalls come from recordings. No OpenAI transcription calls were made, so first-content-word and acoustic delivery completeness are **not measured**. Instrumented self-interruption/delivery counts are not used to certify acoustic completeness, given the audited flaw.
- No missing audio replies were dropped from latency aggregation: all 30 turns in each arm had an audio onset.
- There are five conversation-level replicates, not 30 independent experiments; n=30 describes pooled turn observations only.
- Initial original capture was interrupted by a command timeout before a report existed. It is retained as an incomplete .agent.raw and incomplete-timeout-run.log, not counted as one of the ten complete runs. No completed run was discarded.
- Echo/hesitation and competitors were not rerun.
- Dedicated Chrome/server stopped after completion; virtual audio devices removed and original system defaults restored.

## Decision

Keep the cancellation patch characterized as a liveness/correctness fix, **not a leaderboard optimization**. The next plausible latency intervention remains smaller duration-preserving capture batches or fragmentation-safe TTS presynthesis; neither was implemented or benchmarked here. Repair sustained barge-in and acoustic delivery scoring before presenting a new best-score claim.
