# voiceloop audit — 2026-09-05

Audited local HEAD b6c9d27, package 0.1.10. No live provider benchmark, publish, deployment, or frontend dependency change was performed. Findings below distinguish code reproductions from acoustic measurements. This report replaces the initial exploratory report, whose production-ready conclusion was unsupported.

## Proven local fix: abort blocked by synthesis

`src/voice-agent.js`, StreamingTTS.speak, formerly awaited `e.blobP` unconditionally. Aborting woke an empty-tape waiter but not a consumer awaiting synthesis. Piper inference cannot cancel mid-run; speculative presynth has no turn signal. Therefore stopping/superseding a turn could wait for remaining inference (or indefinitely for a hung synth).

Patch: race the consumer's blob wait against cancellation, remove the listener on exit, retain the instance-level serial synthesis queue. Skip canceled queued jobs before invoking the provider. Never drain or reset the inference queue on abort.

Controlled reproduction, same script against HEAD and patched source, synthesis held for 300ms after cancellation:

| | Original | Patched |
|---|---:|---:|
| Returned before synth released | no | yes |
| Abort → speak returned | 301.14ms | 0.38ms |

This measures turn-loop release, NOT acoustic barge-in or voice→voice latency. Subsequent audio still waits for any non-cancellable inference using the same engine. Two regression tests cover normal and speculative clips and assert no concurrent inference. Full source + benchmark suite: **207/207 pass** (205 before new tests). Independent review found no regression in the patch.

## Confirmed unpatched findings

### 1. Delivery scoring trusts our UI/history rather than recorded audio

- `src/voice-agent.js` skip-on-synth-error branch advances `heardMax` across silent sentences.
- Reproduction: every synth throws, but speak returns all of `Hello world. Everything failed.` as heard (three error events, no audio).
- `bench/blackbox/agent.html:75-77` converts returned assistant text into `reply_done.heardNw`.
- `bench/blackbox/analyze.js:73-74,100-101` suppresses transcription-derived reply_done whenever ANY internal events exist, not merely when a reliable delivery measurement exists.
- `bench/metrics.js` uses spokenRatio for self-interruption detection.

Consequently instrumented SUTs and black-box competitors are not consistently measured by audio truth for delivery. This proves the metric can be wrong; it does not establish that published runs actually had synthesis failures. Headline audio timing is a separate measure.

Fix next: make acoustic delivery the canonical score for every SUT; preserve UI/history counts only as separately named diagnostics. Missing acoustic evidence must be unknown, not success. Add all-silent and partial-failure fixtures. Do not silently change history semantics just to repair a benchmark.

### 2. First-clip presynthesis depends on arbitrary LLM chunk boundaries

`src/voice-agent.js:784-795` examines only `p.first` once. It never pulls enough deltas to finish the first word. `bench/server.js:46` sends fixed 12-character deltas, whereas the production OpenAI adapter forwards individual content deltas.

Reproductions:
- `["Hello world."]` → presynth `Hello`.
- `["Hel", "lo", " world."]` → no presynth, only first delta pulled.
- `["I", " can help."]` → no presynth, only first delta pulled.

LLM prefetch adoption still works; it is the deeper TTS presynthesis optimization that disappears. Fix requires bounded buffered lookahead, exact replay of every consumed chunk, preservation of tool gating, and race tests for adoption/drop during a pending pull. Simply looping over the generator would risk losing text or competing with adoption.

Benchmark addition: identical answer/TTFT/token rate with multiple delta fragmentations. Measure presynth hit rate and commit→audio, not just prefetch adoption.

### 3. A quarter-second microphone batch is on the STT critical path

`src/voice-agent.js:34-45` accumulates 4096 samples at 16kHz before delivering capture to the main thread. That is 256ms of audio per STT feed. A randomly located sample waits about 128ms on average for its batch (up to about 256ms). This affects cloud STT ingress and bootstrap VAD, not Silero's independent steady-state media-stream path.

A 512-sample/32ms experimental capture gives ~16ms mean batching wait: **112ms theoretical batching reduction**, not a measured end-to-end gain. Cost: 8x more main-thread messages. Preroll and bootstrap VAD currently use chunk counts, so changing just 4096 would shrink their time windows 8x and be incorrect. Preserve those windows by duration, validate provider framing, then run live randomized paired A/B across clean, hesitation, echo, and cold start. Do not blindly tune endpoint thresholds at the same time.

### 4. WER uses the correct answer to find a transcript and can reuse it

`bench/metrics.js:114-120` independently selects best-WER final within overlapping windows extending 15 seconds beyond next person start. Two person turns saying `hello`, with only one final after the second, both score WER=0 in the reproduction.

Fix: causal/turn-ID attribution with one-to-one transcript ownership; join split finals where warranted, report ambiguity separately. Narrowing the window alone would unfairly penalize delayed callback APIs.

### 5. Echo safety trades off real short interruptions

Published deepgram+EL row: clean voice→voice 862ms but barge-in 944ms; echo barge-in 1460ms. These are saved results, not new measurements.

`BARGE_IN_MIN_CHARS=6` means isolated `stop` (4), `wait` (4), and `no` (2) cannot trigger partial-based interruption even without echo (a final can still interrupt). Against the audible reply `I can stop that task and wait for you.`, `stop`, `wait`, and `stop stop` classify as echo; `no wait` has only two novel chars. The comment that real interruptions contain novel words is not generally true.

Add real-user short-command, repeated-word, and reply-quotation scenarios before lowering the threshold. Text-only echo filtering cannot reliably distinguish identical user and speaker words. Test AEC/acoustic evidence rather than globally bypassing the echo filter for stop words (which could reintroduce self-interruptions).

## Additional benchmark limits

- Latency aggregation excludes null values: missing replies need explicit failure counts beside survivor latency.
- `analyze.js` derives barge_stop from an overlapping segment's first end; a natural gap followed by resumed speech can look like a stop. Require sustained cessation and check renewed overlap.
- `first content word` matches any of the first six script words, including generic/filler words. It is a lexical heuristic, not a validated semantic-content score.
- Existing nearest-rank p95 formula is valid; p95=max at n=10 is not a bug. Do not alter statistics to make a table look better.
- Synthesis queue detachment does NOT allow overlapping ONNX inference: `_synthQ` remains serial. Awaiting it on abort would worsen the actual bug.
- ElevenLabs non-OK response handling throws after reading text; there is no subsequent double body-read on that path.

## Recommended order

1. Retain reviewed cancellation patch; do not claim a new live benchmark score.
2. Repair audio delivery/failed-turn reporting and add short-interruption fixtures.
3. A/B 32ms capture with duration-preserving preroll/bootstrap behavior.
4. Repair presynthesis fragmentation with bounded single-reader buffering and tool-gate tests.
5. Tune cost: saved RESULTS reports 7.7 LLM requests per turn. This is not just 6% overhead relative to one request; 6% is the increase over the previous 7.25-request policy. Measure prompt tokens and cancellations alongside latency.
